  - PEヘッダ実測：**32bit x86**
  - 埋め込み文字列から実行コアを特定：**吉里吉里Z（Kirikiri Z）実行コア**、スクリプト言語 **TJS2**

## 3. アーカイブ（data.xp3）

- 単一の巨大アーカイブ **data.xp3（1,307,187,984 バイト）** にゲームデータを格納する Kirikiri 標準構成
- 先頭バイト列の実測：
  - マジック `XP3\r\n \n\x1A\x8B\x67\x01`（11バイト）
  - 後続に u64 フィールド群（0x17、フラグ 0x01、0x80…）を持つ Kirikiri Z 世代の拡張ヘッダ形式
  - 最初の格納ファイルは 1×1 PNG（tEXt チャンクに「Warning:」を含む警告画像）
- インデックス領域・データ領域とも高エントロピーで、**目録（ファイル名一覧）すら平文では読めない暗号化**が施されている。サノバウィッチ体験版で使われた suezou ミラーのような平文ミラー配布とは対照的に、本作の体験版は DMM 配布＋暗号化xp3 が正規ルート。
  - 参考：本作の公式ミラーは Getchu（cs_trial.zip）と NetRide で、Wayback Machine には案内ページのみで zip 本体の保存は無かった（2026-11-12確認）

## 5. プラグイン構成（27本）＝ システム機能の地図

Kirikiri Z は本体＋DLLプラグインで機能を足す設計。本作の構成を役割別に整理すると：

### 描画・演出
- `layerExDraw.dll`（レイヤー拡張描画）、`textrender.dll`（テキスト描画）、`windowEx.dll`（ウィンドウ拡張）
- `motionplayer.dll` / `motionplayer_nod3d.dll`（モーション再生。Direct3D使用版／不使用版の2種を用意）
- `psd.dll`（PSD読み込み）、`psbfile.dll`（PSB形式アセット）
- `AlphaMovie.dll`、`krmovie.dll`（動画再生）
- `extrans.dll`（画面遷移効果）、`wfBasicEffect.dll`（基本エフェクト）

### 音響
- `wuvorbis.dll`（Ogg Vorbis）、`wuopus.dll`（Opus）
- `wfTypicalDSP.dll`（音声DSP／エフェクト処理）

### システム・基盤
- `KAGParserEx.dll`（KAGシナリオパーサ拡張）、`kagexopt.dll`（KAG拡張オプション）、`k2compat.dll`（吉里吉里2互換）
- `yuzuex.dll`（ゆずソフト独自拡張）
- `extNagano.dll`（拡張機能）、`PackinOne.dll` / `lzfs.dll`（データ圧縮・展開系）
- `gamepad.dll`（ゲームパッド入力）、`httprequest.dll`（HTTP通信）
- `win32dialog.dll` / `win32ole.dll`（Windowsダイアログ・OLE連携）、`menu.dll`（メニュー）、`getSample.dll`

読み取れる設計思想：エンジン本体は汎用（吉里吉里Z）に保ち、作品固有の要件（モーション再生、PSBアセット、音声DSP、独自拡張 yuzuex）は全部プラグイン側に寄せている。ノベルゲームの「システム」とは、このプラグイン群＋KAGスクリプト側の作り込みのことだと分かる。

## 6. 当サーバーでの起動実験（2026-11-12 実測）

入手した本物の体験版exeを、WoW64対応Wine 11.21（Kron4ekビルド）＋ハイブリッドプレフィックス（syswow64へ32bit DLL 1,113本を移植済み）で起動実験した。

- プロセスは生成されるが、**CPU時間 0 のまま凍結**。ウィンドウは出ない
- プロセスのメモリマップに `wow64.dll` 系・syswow64 モジュールのマッピングが **0件**（32bitコードへの遷移そのものが発生しない）
- サノバウィッチ体験版exe、テスト用32bit exe、syswow64版cmdでも同一の署名を確認済み
- 対照実験：64bit版 hostname.exe は同環境で正常終了（exit 0）
- 結論：このVMのサンドボックスカーネルが32bit互換モード実行そのものを成立させないため、Wine側の構成では回避不能。**本作を含む32bitノベルゲームはこのVMでは起動できない**（64bit exeのタイトルは動作可能）

## 7. VN ARCADE（自作ブラウザノベル）への示唆

- 「商業ノベルのシステム」の実体は、エンジン汎用部＋作品別プラグイン＋KAGスクリプトの三層。ブラウザ実装でも、エンジン（メッセージ表示・セーブ・履歴）と作品データ（シナリオ・演出指定）を分離する現行の VN ARCADE の構成方針は方向として正しい
- 全バイナリ署名のような配布物の完全性担保は、ブラウザ配布ではハッシュ検証やバージョン管理に相当する
- UIの見た目（メッセージウィンドウ、クイックメニュー等）は暗号化のためファイルからは読み取れず、引き続き実プレイ映像・画面からの観察が一次資料になる（本レポートはその代替にはならない）
